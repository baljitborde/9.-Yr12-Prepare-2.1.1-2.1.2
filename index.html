Number Bases
● ~12 minutes

A number base (or radix) is the number of different digits a number system uses. The base also sets the place values: each column is worth the base times the column to its right. In this topic you work with unsigned integers — whole numbers that are zero or positive, with no sign.

Denary (base 10)

Digits 0–9. Place values 1, 10, 100, 1000…

Why needed: the system people use every day, so it is used for input and output that humans read.

Binary (base 2)

Digits 0 and 1. Place values 1, 2, 4, 8, 16…

Why needed: computers are built from billions of transistors, which are switches with two states — off (0) and on (1). All data and instructions are stored and processed in binary.

Hexadecimal (base 16)

Digits 0–9 then A–F (A = 10 … F = 15). Place values 1, 16, 256…

Why needed: a short, human-friendly way to write binary. The computer still uses binary — hex is only for people.

Showing the base: 10 could mean ten, two or sixteen! Write the base as a subscript to remove the doubt: 10102 = 1010 = A16. Hex is also often written with a prefix such as 0x or #, e.g. 0xFF or the colour #FF8800.
Specification 2.1.1 & 2.1.2: You need to know the definition, function and characteristics of binary, denary and hexadecimal and why each is needed, and be able to convert unsigned integers between bases. For units of measurement you need to know bits, nibbles and bytes, the IEC binary prefixes (kibi, mebi, gibi, tebi) and the SI decimal prefixes (kilo, mega, giga, tera), and be able to rank, convert, use and interpret them, and calculate the number of states a number of bits can represent.

Hexadecimal Conversions
● ~15 minutes
Hex → denary
Multiply each digit by its place value (16s and 1s), then add.
3E = 3 × 16 + 14 × 1 = 48 + 14 = 62
Denary → hex
Divide by 16. The answer is the 16s digit; the remainder is the 1s digit.
200 ÷ 16 = 12 remainder 8 → 12 is C, so 200 = C8
Hex ↔ binary: use nibbles

One hex digit stands for exactly 4 bits (a nibble), because 4 bits give 16 combinations. So you never need to go through denary:

Binary → hex
Split into nibbles from the right, convert each nibble.
1101 0111 → D 7 = D7
Hex → binary
Write each hex digit as a 4-bit nibble.
4A → 0100 1010
Benefits of hex
  • Much shorter: 8 bits become 2 hex digits
  • Easier for people to read, remember and type
  • Fewer mistakes than long strings of 0s and 1s
  • Converts directly to and from binary
Where you see hex
  • Colour codes in HTML/CSS, e.g. #007BA6
  • Memory addresses when debugging
  • MAC addresses, e.g. 3C:22:FB:9A:01:7E
  • Error codes
Remember: hex does not save memory or make the computer faster. The value is stored in binary either way. Hex only makes binary easier for people to work with.

Bits, Nibbles, Bytes & Number of States
● ~15 minutes
Bit (b)
A single binary digit: 0 or 1. The smallest unit of data. Symbol: lower-case b.
Nibble
4 bits. Half a byte, and exactly one hex digit, e.g. 1010 = A.
Byte (B)
8 bits. The basic unit for storing data, e.g. one ASCII character. Symbol: capital B.
b or B? Lower-case b means bits; capital B means bytes. 8 Mb is only 1 MB! Network speeds are usually given in bits per second (e.g. Mbps), file sizes in bytes.
How many states can n bits represent?

Each extra bit doubles the number of different patterns, so n bits can represent 2n states.

Bits (n)1234816
States (2n)2481625665 536
Largest unsigned value (2n − 1)1371525565 535

With 2 bits the four states are 00, 01, 10, 11. The largest value is one less than the number of states because counting starts at 0.

Working backwards: to find how many bits you need for a number of states, find the smallest power of 2 that is big enough. For 50 different values: 25 = 32 is too small, 26 = 64 is enough, so you need 6 bits.

Binary (IEC) and Decimal (SI) Prefixes
● ~15 minutes

Large amounts of data need prefixes, just like "kilo" in kilometre. There are two sets of prefixes, and they are not the same size:

IEC binary prefixes (powers of 2)SI decimal prefixes (powers of 10)
kibi (Ki)2101024kilo (k)1031000
mebi (Mi)2201 048 576mega (M)1061 000 000
gibi (Gi)2301 073 741 824giga (G)1091 000 000 000
tebi (Ti)240≈ 1.1 × 1012tera (T)10121 000 000 000 000

Each binary prefix is 1024 times the one before (1 MiB = 1024 KiB). Each decimal prefix is 1000 times the one before (1 MB = 1000 kB). The specification writes kilo as K; you will also see a lower-case k.

Use binary prefixes for…
data capacity and file sizes — RAM, storage and files, e.g. 16 GiB of RAM, a 3.2 MiB photo. Memory is addressed in powers of 2, so the sizes come out as exact, whole numbers.
Benefit: accurate for memory. Drawback: less familiar; many people and some software still write "KB" when they mean 1024 bytes.
Use decimal prefixes for…
transmission speeds — e.g. a 100 Mbps broadband connection is 100 000 000 bits per second. Storage manufacturers also label drives in decimal units.
Benefit: familiar round numbers that match the metric system. Drawback: do not match memory sizes, which causes confusion.
Why the difference grows: 1 KiB is only 2.4% bigger than 1 kB, but 1 TiB is about 10% bigger than 1 TB. That is why a new "1 TB" drive shows up as only about 931 GiB on a computer.

Converting and Calculating with Units
● ~15 minutes
Binary units ladder
bit× 8 →byte
byte× 1024 →KiB
KiB× 1024 →MiB
MiB× 1024 →GiB
GiB× 1024 →TiB

Going to a bigger unit: divide. Going to a smaller unit: multiply. For decimal units, use 1000 instead of 1024.

Worked examples

5 MiB in KiB: 5 × 1024 = 5120 KiB

6144 MiB in GiB: 6144 ÷ 1024 = 6 GiB

3 KiB in bits: 3 × 1024 × 8 = 24 576 bits

Writing expressions: 4 GiB = 4 × 230 bytes; 2 TB = 2 × 1012 bytes.

Download time = file size in bits ÷ speed in bits per second
How long does a 2 MiB file take on a 8 Mbps connection?
1. File size in bits: 2 × 220 × 8 = 16 777 216 bits
2. Speed: 8 Mbps = 8 × 106 = 8 000 000 bits per second
3. Time = 16 777 216 ÷ 8 000 000 ≈ 2.1 seconds
Common mistakes: forgetting to × 8 to turn bytes into bits; using 1000 for a binary prefix (or 1024 for a decimal one); and mixing up b and B.

✓ Summary — Topics 2.1.1 & 2.1.2
Number bases: denary (base 10) for people, binary (base 2) for computers because transistors have two states, hexadecimal (base 16) as a short, readable form of binary.
Binary ↔ denary: add the place values with a 1 under them; to go the other way, subtract place values from the largest down.
Hexadecimal: digits 0–9 and A–F; multiply by 16s and 1s to get denary; one hex digit = one nibble, so convert to binary 4 bits at a time.
Units: bit (b) = 0 or 1; nibble = 4 bits; byte (B) = 8 bits. n bits give 2n states, from 0 to 2n − 1.
Prefixes: IEC binary (Ki, Mi, Gi, Ti) go up in 1024s and are used for file sizes and capacity; SI decimal (k, M, G, T) go up in 1000s and are used for transmission speeds.
Calculating: multiply to a smaller unit, divide to a bigger one; × 8 for bytes to bits; time = size in bits ÷ speed in bits per second.
